## 4. 사용 흐름에서 헷갈리는 곳

1. 두 번째 브라우저에서 트리의 폴더를 바로 고르면 기본값이 "새 공유 폴더 만들기"라 공유 폴더가 중복 생성됨 (Onboarding.tsx:190).
2. 삭제는 한 건이라도 양쪽 브라우저에서 승인해야 함. 가장 큰 마찰.
3. 미리보기에 이 브라우저 폴더 이름이 "…"로 나옴 (Onboarding.tsx:413).
4. "백업: 저장됨"이 실제 백업보다 먼저 표시됨 (Onboarding.tsx:482 vs service.ts:583).
5. 오류가 `NESTED_BINDING` 같은 코드로 노출됨 (Onboarding.tsx:156·334·501 외).
6. 표 헤더 "Title", 휴지통 "(root)"가 영어.
7. "서버/계정/공유 폴더" 용어 혼용. "다른 브라우저의 변경 / 이 브라우저의 변경"으로 통일 권장.
8. 팝업에 실시간 연결 여부·대기열 숫자 등 엔진 정보가 많음.
9. 계정 삭제가 "로그아웃 후 5분 안에 재로그인"을 요구함. 삭제 창 안에 "Google로 다시 확인" 버튼 권장.
10. 다른 브라우저 연결 해제에 확인 창이 없음 (Settings.tsx:256).
11. 막다른 길: "중단된 작업" 링크가 해당 탭으로 안 감. `연결 폴더 없음` 상태의 "다시 선택"이 기존 공유 폴더에 재연결할 길이 없을 가능성.
12. 두 Mac의 Chrome 자체 동기화가 켜져 있으면 반향·중복 가능, 경고 없음.
13. 확장 재설치 후 재병합 시 중복이 생기는지 미검증.
14. 설정의 동기화 스위치 셋(자동 동기화·실시간·확인 간격)은 사용자에겐 같은 개념.

## 7. 문제없음으로 확인된 것

- RPC에서 다른 계정 데이터를 읽거나 쓰는 경로는 찾지 못함. 모든 처리가 로그인 토큰의 보관함으로 한정되고, 로그인 사용자도 데이터 스키마에 직접 접근 불가(확인).
- 계정 삭제 함수의 JWT 처리 방식은 안전함.
- 전송 중 강제 종료 후 같은 opId 재전송, 변경 수신 재실행, 스냅샷 재구성, 수정·이동·삭제 도중 종료 후 수렴, 재시도 alarm 복구.
- 저장소에 커밋된 비밀값 없음(확인).
